# ADR-0029: Оценка ячеек сетки — референс-объект и EBM-декомпозиция локационных термов

**Статус:** Proposed
**Дата:** 2026-08-21
**Связано:** [ADR-0016](0016-quartet-of-models.md) (EBM — White Box), [ADR-0027](0027-tsorf-on-grid.md) (сетка ЦОФ), [ADR-0028](0028-representativeness-report.md) (репрезентативность), эпик 001

## Контекст

Карта стоимости сейчас покрывает только ячейки, где есть объекты НСПД (per-object предсказания → hex_aggregates). Пользовательский вопрос — «сколько стоил бы м² в ячейке, где нет объектов» — требует прогноза на всей сетке Слоя 1 (177 131 ячейка res 10), включая 89 % ячеек вне обучающей выборки (ADR-0028).

Модель (квартет ADR-0016, EBM как основная для этой задачи) обучена per-object: предсказывает `synthetic_target_rub_per_m2` по 237 фичам — локационным (характеристики места) и объектным (площадь, этажность, материал, …). У ячейки без объекта объектных атрибутов нет.

## Отвергнутый вариант: «объект-призрак» с экстремальными атрибутами

Идея «скормить модели объект с нулевой площадью / нулём этажей / отсутствующими стенами» отвергнута:

- Модель не знает концепции «нет объекта» — такой вектор лежит далеко за пределами обучающего распределения по объектным осям (`area_m2 = 0` при обучающем минимуме в десятки м²). Это экстремальная экстраполяция shape-функций EBM в область, где они никогда не видели данных; результат численно определён, но семантически бессмыслен.
- «Отсутствие стен» не выразимо: `materials` — номинальная фича, у неё нет значения «нет», а `__missing__` означает «неизвестно», не «отсутствует».
- Даже если бы число получилось, интерпретировать его как «ценность локации» нельзя — объектные термы с экстремальными значениями внесли бы непредсказуемый вклад.

## Решение: два честных продукта на EBM

Оба — per cell, per class, на якорных ячейках res 10 (сетка ADR-0027). Модель — финальный full-data EBM (`ebm_model.pkl`) последнего quartet-рана класса.

### Продукт 1: референс-объект

Для каждого класса фиксируется **типовой объект** — шаблон объектных атрибутов из gold этого класса:

- непрерывные/целые (`area_m2`, `levels`, `flats`, `year_built`, `underground_floors`, `polygon_*`) — **медиана** (целые округляются);
- категориальные (`materials`, `vri`, `category_zem`) — **мода**;
- производные (`age_years`, `age_years_sq`, `era_category`) — **пересчитываются из медианного `year_built`**, а не медианируются сами, чтобы шаблон был внутренне согласован.

Прогноз EBM для ячейки = «цена типового объекта, поставленного в эту ячейку»: объектные атрибуты — из шаблона, локационные — из ячейки (Слой 1 + досчитанный enrichment, см. ниже).

Для **landplot** шаблон строится отдельно по каждому частому `vri` (топ-5 по числу объектов) плюс общий `default` — ВРИ сильнее прочих атрибутов определяет цену участка, один шаблон был бы нечестным. Варианты — **отдельные строки** выходного слоя с колонкой `reference_variant` (а не колонки-пивот: схема одна, потребителю проще фильтровать).

### Продукт 2: location_score — EBM-декомпозиция локационных термов

EBM аддитивен: `predict(x) = intercept + Σ fᵢ(xᵢ)` (плюс 10 парных взаимодействий). `eval_terms` даёт вклад каждого терма построчно. Термы делятся на:

- **локационные** — все фичи терма не являются объектными атрибутами;
- **объектные** — хотя бы одна фича терма — объектный атрибут (включая парные взаимодействия «объект × локация» — они исключаются целиком, т.к. их значение зависит от шаблона).

`location_score = intercept + Σ (локационные термы)`, в ₽/м².

**Семантика (важно):** location_score — это **не прогноз цены** и не «цена пустой ячейки». Это аддитивная ценность локации при выкинутых объектных термах. Объектные термы в среднем по выборке не нулевые, поэтому location_score систематически отличается от reference-цены — обе величины публикуются рядом, разница читается как «вклад типового объекта». Объектные атрибуты, участвующие в relative-фичах (`levels__rel_p7_*` и т.п.), считаются объектными термами; `count_p7/p8` (плотность объектов в parent-ячейке) — локационные.

## Досчёт per-cell фич ADR-0021..0025

Сетка Слоя 1 (ADR-0027) покрывает 119 ЦОФ, но фичи ADR-0021..0025 (DEM, road-class, изохроны, CBD, heritage, ЗОУИТ, oktmo_*) существуют только per-object. Они досчитываются per-cell в новый feature set `enrichment` (`data/silver/features/…/feature_set=enrichment/resolution=10/`), теми же etl-функциями, что и per-object (они принимают DataFrame с `lat`/`lon` — центроиды ячеек проходят через тот же код):

| Блок | Источник | Механизм per-cell |
| --- | --- | --- |
| `dist_to_cbd_m` | константа региона (Settings.cbd_coords) | haversine от центроида |
| DEM (`elevation_m`, `slope_deg_local`, `relative_relief_500m_m`) | silver DEM rasters | sample по центроиду (`compute_object_dem_features`) |
| road-class (`nearest_road_class`, `dist_to_*_m` ×5) | OSM ways (major raw + minor parquet) | `compute_nearest_road_features` на центроидах (STRtree, UTM-39N) |
| isochrone (`iso15_*` ×3) | кэш res 11 (ADR-0024) | join по res-11 ячейке центроида (`join_isochrone_features`) |
| heritage (×4) | silver ОКН | `compute_object_heritage_features` на центроидах |
| ЗОУИТ (×3) | silver zone polygons | `compute_object_zouit_features` на центроидах (STRtree, bbox-фильтр внутри) |
| oktmo + макро (`oktmo_*` ×6) | gold-объекты + EMISS wide table | **пространственная пропагация** (см. ниже) → `compute_object_macro_features` |

**OKTMO/территориальные категории per cell.** У ячейки нет адреса и кадастрового номера — объектный путь (ГАР lookup) неприменим, а полигонов поселений в данных нет. Поэтому территориальные атрибуты (`oktmo_full`, `settlement_name`, `mun_okrug_*`, `okato`, `postal_index`, `kadnum_quarter`) наследуются от gold-объектов **иерархической модой по H3**: мода в самой ячейке res 10 → мода в parent res 9 → res 8 → res 7 → null. `intra_city_raion` — честный spatial join центроида по полигонам районов OSM (`kazan-agg-raions.geojsonseq`), как в объектном пайплайне. Это аппроксимация: на неосвоенной территории OKTMO присваивается от ближайшего освоенного окружения; ошибка присвоения на границах муниципалитетов задокументирована как ограничение.

**Relative-фичи** (`*__rel_p{7,8}_*`, `count_p{7,8}`): при обучении агрегаты parent-ячеек считались по самой обучающей выборке (все классы вместе, до нарезки). Для ячеек применяются **те же агрегаты из gold** (медиана/p25/p75/count per parent per фича): значение ячейки (или шаблона — для объектных базисов) минус медиана объектов parent'а и т.д. Ячейки в parent'ах без объектов получают null — EBM это штатное состояние.

## Репрезентативность (связь с ADR-0028)

ADR-0028 не содержит per-cell флагов — отчёт даёт вердикты ok/moderate/shift **per feature × segment** и покрытие per class (расход с исходным брифом, следуем коду). Поэтому:

- per cell выставляются `n_sample_objects` (число объектов класса в ячейке) и `sample_covered` (bool) — прямая мера «модель здесь училась»;
- сводка вердиктов (доля shift-фич класса) идёт в `_meta.json` рядом с parquet;
- предсказания на `sample_covered = false` (≈89 % территории) — экстраполяция на сдвинутых распределениях (ADR-0028: 49 из 119 ЦОФ со shift); потребитель обязан видеть флаг.

## Выходной слой

`data/gold/cell_valuation/region=RU-KAZAN-AGG/asset_class={class}/data.parquet`:

| Колонка | Тип | Смысл |
| --- | --- | --- |
| `h3_index` | Utf8 | якорная ячейка res 10 |
| `lat`, `lon` | Float64 | центроид |
| `reference_variant` | Utf8 | `default` или значение `vri` (landplot) |
| `reference_rub_per_m2` | Float64 | продукт 1: цена референс-объекта |
| `location_score_rub_per_m2` | Float64 | продукт 2: intercept + локационные термы |
| `n_sample_objects` | Int64 | объектов класса в ячейке |
| `sample_covered` | Boolean | ячейка покрыта обучающей выборкой класса |

Строки: apartment/commercial/house — по одной на ячейку (177 131); landplot — 6 вариантов на ячейку. `location_score` у landplot одинаков между вариантами (не зависит от шаблона) — денормализация сознательная. Рядом `_meta.json`: состав шаблона(ов), id модельного рана, sanity-метрики, сводка репрезентативности.

## Apartment-класс

Включён, но: класс тонкий (1 089 объектов, покрытие сетки 0.5 %, ADR-0028), а «квартира без дома» физически маргинальна — reference-цена квартиры в чистом поле читается как «цена м² типовой квартиры, если бы здесь стоял типовой дом». Потребителю рекомендуется смотреть apartment только на освоенных ячейках.

## Последствия

- Слой 1 получает 7-й feature set `enrichment` (ADR-0021..0025 per-cell).
- `EbmQuartetModel` расширяется `eval_terms`/`intercept`/`term_feature_indices`; порт EBM-лоадера расширяется до скоринг-интерфейса (обратно-совместимо: `explain` сохраняется).
- Новый usecase `BuildCellValuation` + скрипты `build_cell_enrichment_features.py`, `build_cell_valuation.py`.
- UI/API не трогаем — только gold-слой и ADR.

## Риски и границы

- **Экстраполяция** — главный риск (см. связь с ADR-0028 выше). Флаг `sample_covered` обязателен для потребителя.
- **Согласованность шаблона**: медианы независимых атрибутов не обязаны соответствовать одному реальному объекту (`polygon_*` взяты медианами независимо от `area_m2`). Это компромисс «типовости»; задокументировано.
- **OKTMO-пропагация** ошибается на границах муниципалитетов и в неосвоенной зоне.
- **Mixed-термы** (объект × локация) исключены из location_score целиком — часть локационного сигнала, проявляющегося только во взаимодействии с объектом, теряется (у house это 2 из 10 взаимодействий).
- Темпоральной оси нет — оценка «на дату обучающей выборки».
