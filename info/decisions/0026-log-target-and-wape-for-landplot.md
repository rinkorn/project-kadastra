# ADR-0026: Log-таргет и WAPE для земли (landplot)

**Статус:** Accepted
**Дата:** 2026-08-17
**Реализует:** [ADR-0016](0016-quartet-of-models-and-loss-on-simplification.md), блок 5 — корректная относительная метрика для класса с мелким знаменателем ₽/м².

## Контекст

В ADR-0016 зафиксировано, что MAPE на landplot «структурно зашумлен» (253 % у CatBoost) — из-за **крошечного знаменателя** `₽/м²`: у земли цена за м² на 2–3 порядка ниже, чем у квартир, поэтому маленькая абсолютная ошибка раздувается в гигантский процент. Две связанные проблемы:

1. **Метрика.** `MAPE = mean(|error| / |y|)` нестабильна при `y → 0`: асимметрична (недооценка ≤ 100 %, переоценка неограничена) и доминируется самыми дешёвыми участками.
2. **Цель модели.** Цены земли сильно логнормальны (разброс на порядки). Обучать на сыром `y` — значит давать модели несимметричную относительную цель, что хуже для аддитивных/линейных моделей квартета.

## Решение

Два изменения в `TrainQuartet`:

1. **Log-таргет для landplot.** Для `AssetClass.LANDPLOT` квартет обучается на `y_model = log(y)`; OOF-предсказания перед записью в `*_oof_predictions.parquet` и перед расчётом сравнительных метрик экспоненцируются обратно в `₽/м²`. То есть **ничего downstream не меняется** — инспектор, карта и hex-агрегаты по-прежнему видят цены в исходной шкале.

2. **WAPE + rmse_log в метриках.** В `quartet_metrics.json` добавляются:
   - `wape = Σ|y − ŷ| / Σ|y|` — агрегированный относительный процент, устойчивый к мелкому знаменателю (в отличие от MAPE). Считается в исходной шкале для всех классов — единая сопоставимая метрика.
   - `rmse_log = sqrt(mean((log y − log ŷ)²))` — только для landplot; это и есть «симметричная относительная ошибка», которую теперь и смотреть для земли.
   - поле `target_transform: "log" | "identity"` — чтобы потребитель метрик знал, в какой шкале считаны `mean_mae/rmse/mape` (для landplot они в log-шкале).

Отчётная картина для landplot: **Spearman** (ранг) + **WAPE** (агрегированный процент) + **rmse_log** (симметричная относительная ошибка). MAPE для земли по-прежнему считается, но не репрезентативен.

## Почему так

- **WAPE, а не MdAPE/другое.** WAPE — единственный относительный процент, который делим на сумму, а не на пообъектный знаменатель; это стандартный «бизнес-процент» (Σ ошибок / Σ цен), сопоставимый между классами.
- **log-таргет, а не просто смена метрики.** Это чинит не только отчёт, но и **само обучение**: симметричная относительная цель лучше подходит для логнормальных цен и для аддитивных моделей (EBM/Naive), которые иначе «тянутся» за дорогими объектами.
- **exp обратно, а не хранить log.** Хранение OOF в исходной шкале изолирует изменение внутри `TrainQuartet` — ни один потребитель OOF не меняется.

## Рассмотренные альтернативы

| Вариант | Почему отвергнут |
| --- | --- |
| Только WAPE, без log-таргета | Чинит метрику, но не обучение; модель всё ещё на асимметричной цели. |
| MdAPE (медиана APE) | Робастен к выбросам, но знаменатель всё равно мелкий — полумера. |
| Хранить OOF в log-шкале | Ломает все downstream-консумеры (инспектор/карта/hex), требует их переписывания. |
| Общая целевая метрика только MAE | MAE не относительный — не сопоставим между классами с разным масштабом цены. |

## Влияние

- `TrainQuartet.execute` для landplot теперь обучает на log-таргете; артефакты (`quartet_metrics.json`, OOF-паркеты) по схеме совместимы с прежними (OOF в ₽/м²).
- `mean_mae/rmse/mape` для landplot меняют смысл (становятся log-шкальными) — помечено `target_transform="log"`.
- Повторный прогон квартета на landplot даст новые `wape`/`rmse_log`; старые `mean_mape` сравнивать между прогонами нельзя без учёта трансформа.
