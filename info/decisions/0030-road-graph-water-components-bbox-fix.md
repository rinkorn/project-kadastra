# ADR-0030: Починка пешеходного road-графа — фантомные переправы, выпавшие мосты, компоненты связности, bbox, теги

**Статус:** Accepted (код; пересчёт данных — follow-up)
**Дата:** 2026-08-21
**Контекст:** [ADR-0011](0011-graph-based-distance-features.md) (графовые дистанции), [ADR-0024](0024-road-network-advanced-features.md) (road-class фичи, isochrone-кэш), [ADR-0027](0027-tsorf-on-grid.md) (ЦОФ на сетке)

## Контекст

Пешеходный граф (`data/silver/road_graph/edges.parquet`, 343 752 узла в главной компоненте) питает `dist_metro_m` / `dist_entrance_m`, `walk_dist_to_*` (Слой 1), isochrone-кэш (ADR-0024). Аудит графа против `data/raw/osm/kazan-agg-water.geojsonseq` и анализ компонент связности выявили пять дефектов.

## Дефекты (проверено фактами)

1. **Фантомные переправы.** 193 ребра `edges.parquet` идут по воде более чем на 30 м (пересечение сегмента с водными полигонами `kazan-agg-water.geojsonseq`). Включая цепочку ~2.3 км через русло Волги к Верхнему Услону, где моста нет: (55.7969,48.9787)→(55.7957,48.9797)→(55.7942,48.9813)→(55.7917,48.9838)→(55.7894,48.9861)→(55.7863,48.9892)→(55.7834,48.9922)→(55.7803,48.9925). Дейкстра «ходит» через Волгу пешком — все пешеходные дистанции правого берега занижены.
2. **Выпавшие мосты.** Overpass-запрос в `scripts/download_walking_network.py` отрезал `highway~^(motorway|trunk|motorway_link|trunk_link|construction|proposed)$` — с ними выпали настоящие мосты с пешеходной частью (напр. Миллениум, `highway=trunk`).
3. **176 компонент связности.** Главная — 343 752 узла, плюс 175 ошмётков (несвязанные обрезки дорог, острова, обрывы после удаления переправ). `_snap` в `NetworkxRoadGraph` брал ближайший узел не глядя на компоненту → объекты у дорог-огрызков получали inf → в `compute_object_metro_features` inf превращался в сентинел `1e9` м → пятна-артефакты «миллиард метров» (замерено: 490 объектов landplot, 0.1–0.2 % выборки). Модель читала сентинел как «очень далеко», хотя это «неизвестно».
4. **Краевые эффекты.** Граф вырезан строго по bbox агломерации (`55.5..56.05, 48.7..49.55`) — объекты у края получали завышенные дистанции: путь упирался в обрез графа, а не в реальный конец сети.
5. **Теги потеряны.** `edges.parquet` хранил только `(from_lat, from_lon, to_lat, to_lon, length_m)` — без `highway`/`bridge`/`tunnel` невозможен ни водный фильтр постфактум, ни road-class фичи ADR-0024 из графа (пришлось отдельно качать minor roads в `kazan-agg-minor_road_ways.parquet`).

## Решение

1. **Скачивание** (`scripts/download_walking_network.py`):
   - Дефолтный bbox расширен на ~12 км во все стороны (`55.39..56.16, 48.51..49.74`; 12 км ≈ 0.108° lat, ≈ 0.192° lon на широте Казани) — запас против «пути в обрез» для краевых объектов.
   - Overpass-запрос — union: прежняя ветка классов + все ways с `bridge=yes` независимо от класса (в т.ч. trunk). `motorway`/`motorway_link` исключены даже на мостах — пешеходов там нет. Overpass-union дедуплицирует элементы по (type, id), двойных рёбер не будет.
2. **Теги в артефакте** (`build_road_graph_edges_from_overpass`): edges.parquet получает колонки `highway`, `bridge`, `tunnel`, `layer` (Utf8, null при отсутствии тега). Это сырьё и для водного фильтра, и для будущих road-class фич ADR-0024 прямо из графа.
3. **Водный фильтр** (`kadastra/etl/road_graph_water_filter.py`, вызывается из `scripts/build_road_graph_artifact.py`): ребро выкидывается, если его сегмент пересекает union водных полигонов более чем на **30 м** (`DEFAULT_MAX_WATER_CROSSING_M`, CLI-флаг `--max-water-crossing-m`) И у way нет `bridge`/`tunnel` (тег есть и ≠ `no`). Порог 30 м покрывает фаззи-береговую линию OSM-полигонов (набережные клиппят пару метров полигона), а настоящая переправа через русло — на порядок длиннее. Геометрия — UTM 39N + STRtree + векторный `shapely.intersection`/`length` (паттерн ADR-0014). При отсутствии файла воды фильтр пропускается с warning — артефакт всё равно собирается (идемпотентность сохранена).
4. **Главная компонента** (`NetworkxRoadGraph.from_edges`): после сборки оставляется только largest connected component; узлы переиндексируются, отброшенные узлы/рёбра логируются (stdlib `logging`). `_snap` теперь по построению снапит только в главную компоненту — inf-недостижимости из-за ошмётков больше не возникает.
5. **Null вместо сентинела** (`object_metro_features`, `cell_graph_distance_features`): недостижимость (inf от графа) и пустой список POI → **null** в `dist_metro_m` / `dist_entrance_m` / `walk_dist_to_*_m`. CatBoost/EBM обрабатывают NaN нативно (`object_feature_matrix` уже отдаёт NaN для missing) — null честно говорит «неизвестно» вместо фейковых «очень далеко». Счётчики (`count_stations_1km` и т.п.) остаются 0.
6. **Пересборка на VM** (`.github/workflows/rebuild-dev-stage-data.yml`): новые шаги после скачивания входов — `download_walking_network.py --force` → `build_road_graph_artifact.py` (с водным файлом из S3) → пересчёт `build_cell_metro_features.py`, `build_cell_graph_distance_features.py`, `build_isochrone_cache_per_hex.py` → выгрузка `silver/road_graph`, `silver/features`, `silver/isochrone_cache` на S3. Запуск — отдельным шагом после мержа.

## Альтернативы

- **Фильтровать воду на стороне Overpass** (`way[highway][!bridge]` минус пересечение с водными relations) — Overpass не умеет геометрический анти-join по полигонам слоёв; постобработка shapely проще и проверяема юнит-тестами.
- **Снап с лимитом дистанции** (snap > N км → inf) вместо выбрасывания мелких компонент — оставляет в графе мусор и не чинит объекты, живущие рядом с ошмётком; выбрано удаление компонент.
- **Оставить сентинел 1e9** — отвергнуто: модель не отличает «1e9 = неизвестно» от «1e9 = очень далеко», а это разные физические ситуации.

## Последствия

- **Пересчёт (follow-up, отдельный шаг):** прогон workflow `rebuild-dev-stage-data` на VM → новые `edges.parquet` (с тегами, без фантомов), новые `dist_metro`/`walk_dist_*` ЦОФ сетки и isochrone-кэш → rebuild `gold/valuation_objects` (object features пересчитаются из Слоя 1) → rebuild `gold/hex_aggregates` → **переобучение затронутых классов** (в первую очередь landplot/house — там сидели 490 сентинел-объектов и краевые эффекты) по протоколу ADR-0027 «Замечание для будущих переобучений».
- **Схема edges.parquet расширена** — `NetworkxRoadGraph.from_parquet` читает прежние 5 колонок и совместим в обе стороны (старые артефакты без тегов грузятся, новые колонки игнорируются).
- **Контракт фич изменился:** `dist_metro_m`, `dist_entrance_m`, `walk_dist_to_*_m` могут быть null. Потребители: CatBoost/EBM — нативно; `object_synthetic_target` (ADR-0004, legacy-синтетика) при null даст null target — такие строки отвалятся на обучении, что корректно.
- **Ожидаемые эффекты на данных:** исчезает 2.3-км переправа через Волгу (правый берег получает честные дистанции), возвращается Миллениум и др. trunk-мосты, ~175 ошмётков перестают притягивать снапы, краевые объекты теряют «путь в обрез».
- ADR-0027 («Непроходимые точки → сентинел 1e9») обновлён: семантика теперь null.
