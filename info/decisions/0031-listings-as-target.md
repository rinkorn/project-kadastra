# ADR-0031: Листинги как market-target — что делать с MVP-выгрузкой Циан/Яндекс/Авито

**Статус:** Accepted (вариант б, 2026-08-21)
**Дата:** 2026-08-21
**Связано:** [ADR-0010](0010-methodology-compliance-roadmap.md) (трек 1 — target), [ADR-0016](0016-quartet-of-models-and-loss-on-simplification.md) (квартет моделей), [ADR-0025](0025-misc-enrichment-cbd-heritage-zoouit.md) / [ADR-0027](0027-tsorf-on-grid.md) / [ADR-0029](0029-cell-valuation-reference-object.md) (pipeline ЦОФ и cell valuation), [info/listings-scraping-mvp.md](../listings-scraping-mvp.md) (сам сбор), разведка `.tmp_research/track1-listings-assessment.md` (2026-08-21)

## Контекст

Target обучения сейчас — `cost_index` из ЕГРН, официально **interim placeholder** (см. статус target в [info/project.md](../project.md)). Правильный target — рыночные сделки; источника сделок (Росреестр/ППК) у проекта нет. В апреле собран research-MVP листингов (Циан/Яндекс/Авито, 2 556 уникальных квартир, [listings-scraping-mvp](../listings-scraping-mvp.md)), но в train pipeline он не подключён.

Разведка пригодности (`.tmp_research/track1-listings-assessment.md`, 2026-08-21) по дампу `data/silver/listings-mvp/all.parquet` установила:

| source | city | rows | lat/lon coverage | медиана ₽/м² |
| --- | --- | --- | --- | --- |
| cian | Казань | 1268 | **100 %** | 221 510 |
| yandex_realty | Казань | 651 | **0 %** | 226 000 |
| yandex_realty | Иркутск | 441 | **0 %** | 159 236 |
| avito | Казань | 196 | **0 %** | 197 979 |

Ключевые факты:

1. **Только CIAN пригоден как geo-target**: coords 100 %, material 93 %, rooms 91 %, floor 100 %, build_year 60 %; все 1268 в bbox агломерации. Хвосты p1=112K / p99=700K ₽/м² — выбросы (59K ₽/м² — вероятно гаражи/апарт-ошибки; 908K — элит или миспрайс), нужна чистка квантилями перед обучением.
2. **Yandex: координат нет в raw HTML вообще** — их подгружает отдельный maps-API, который не сохранялся. Повторный парс существующего сырья coords не даст. Единственный путь — геокодинг по адресному тексту (качество адресных строк требует измерения).
3. **Avito**: 196 строк, без coords, сбор упёрся в IP-блок на p=5 — маргинально.
4. Кросс-площадочные дубли: 36 кластеров / 75 строк по (lat, lon, area, price) — при объединении источников дедупликация обязательна.
5. CIAN Казань (1268) сопоставим по размеру с текущей обучающей выборкой apartment (1089) — один CIAN удваивает сигнал по квартирам, причём с рыночным (ask) ценником вместо кадастрового.
6. Ask vs deal переоценка ~+10–15 % систематична: для ранжирования и Δ-метрик допустимо, для абсолютной калибровки нужна поправка (можно оценить по парам листинг↔ЕГРН в одном доме).
7. Листингов по house/commercial/landplot **нет вообще** — там target остаётся заблокированным независимо от решения по apartment.

## Варианты

### (а) Не использовать листинги как target вообще

CIAN-квартиры подключаются только как дополнительная валидация (сравнение предсказаний модели с ask-ценами, ранговая корреляция по ячейкам), обучение остаётся на `cost_index` ЕГРН.

- **За:** ноль риска для pipeline; не вносим ask-bias (+10–15 %) в target; Yandex/Avito всё равно непригодны.
- **Против:** `cost_index` — официально broken-выход, который проект ставит целью превзойти ([info/project.md](../project.md), ADR-0010); модель продолжает обучаться на placeholder'e; рыночный сигнал, уже лежащий на диске, не используется; трек 1 остаётся заблокированным.

### (б) Listings-as-target только для apartment на CIAN

1268 CIAN-квартир становятся interim market-target класса apartment (вместо или в смеси с `cost_index`), с обязательной предобработкой:

- чистка выбросов квантилями (хвосты p1/p99 по факту разведки);
- join к NSPD-объектам по geo+area для обогащения объектными фичами (листинг даёт rooms/floor/area/material, но объектные атрибуты дома — из НСПД);
- калибровка ask→deal: поправка по парам листинг↔ЕГРН в одном доме (величина поправки **требует измерения** — разведка даёт только ориентир +10–15 %);
- дедупликация по (lat, lon, area, price) перед любым объединением источников.

- **За:** единственный гео-пригодный рыночный сигнал, доступный сейчас; удваивает сигнал по квартирам (1268 против 1089 в текущей выборке); разблокирует трек 1 для самого массового класса; выборка сопоставима с текущей — эффект на метриках квартета (ADR-0016) измерим сразу.
- **Против:** ask≠deal — без калибровки абсолютные значения смещены; 1268 строк — мало для уверенного переобучения per-class модели, выигрыш в MAPE/WAPE не гарантирован и требует замера; покрытие листингов по территории vs обучающей выборки НСПД **требует измерения** (сдвиг в сторону активных ЖК может ухудшить репрезентативность, см. ADR-0028); house/commercial/landplot это не разблокирует.

### (в) Доскрапинг (Yandex-геокодинг, добивка Avito, другие классы)

Перед решением по target дообогатить выборку: геокодить 651 Yandex-карточку Казани по адресным строкам, доскачать Avito после снятия IP-блока, запустить scrape по house/land/commercial.

- **За:** +651 квартира Казань потенциально; закрывает дыру по другим классам.
- **Против:** качество адресных строк Yandex **требует измерения** — до замера геокодабельности объём реального прироста неизвестен; Avito маргинален (196 строк, IP-блок); ToS всех площадок запрещает automated-сбор (см. [listings-scraping-mvp](../listings-scraping-mvp.md)) — доскрапинг углубляет research-нарушение вместо движения к легитимному договору; сегментные scrape-сессии (земля/дома/коммерция) — это новый объём работ с теми же антибот-рисками.

### Риск: отравление выдачи CIAN после детекта бота

Владелец фиксирует, что CIAN «через некоторое время, распознав бота, начал подкидывать мусор». Ретро-проверка собранного дампа (`data/silver/listings-mvp/all.parquet`, 2026-08-21):

- явных сигнатур отравления **не найдено**: 1268 строк, все `listing_id`/`url` уникальны (переиспользования id с разными ценами нет), нулевых цен/координат нет, кластеры по 8–12 листингов на одной точке соответствуют многоквартирным домам (CIAN даёт координаты дома) — это норма, а не мусор;
- **подозрительные зоны**: блок страниц 25–30 с медианой 287–430K ₽/м² (против типичных 200–240K) и разреженный хвост страниц 55+ (вплоть до p=183 с 1 строкой — при обычной выдаче ~54 страницы для Казани);
- raw HTML страниц не сохранился (чищен при очистке данных), поэтому полная ретроспективная проверка невозможна — вердикт по хвосту выдачи остаётся недоказанным в обе стороны.

Митигации при реализации варианта (б):

1. **Join к НСПД как жёсткий мусор-фильтр**: листинг должен сматчиться с реальным объектом/домом (geo+area, `floor ≤ floors_count`, согласованность build_year/материала дома). Отравленная карточка с выдуманными атрибутами такой join не пройдёт; несматченные листинги — отдельная корзина с замером доли (это и есть измерение масштаба отравления).
2. Sanity-правила до обучения: квантильная чистка ₽/м² (уже в варианте б), `10 ≤ area ≤ 300 м²`, `floor ≤ floors_count`, цена не кругло-повторяющаяся.
3. Хвост страниц >54 — под отдельную проверку или отбросить (макс. ~15 строк, потеря несущественна).
4. Контрольная валидация: ранговая корреляция ask-цен с предсказаниями `cost_index`-модели по ячейкам — системный провал корреляции на подвыборке = сигнал отравления.

## Рекомендация (предлагается владельцу)

**Вариант (б) как основной, с элементами (а):** CIAN-листинги — interim market-target для apartment (чистка квантилями, join к НСПД, калибровка ask→deal по домам с последующим измерением поправки), при этом `cost_index`-модель сохраняется как baseline для сравнения на тех же spatial-CV фолдах — то есть CIAN-данные одновременно служат и валидацией, и target'ом в параллельном ране. Вариант (в) — только опциональным вторым шагом и только после замера качества адресных строк Yandex; доскрапинг других классов отдельным решением, т.к. это новый scrape, а не использование собранного.

Обоснование: по фактам разведки CIAN — единственный источник с полным geo-coverage, его объём сопоставим с текущей обучающей выборкой apartment, а ask-bias систематичен и оценим по парам в одном доме. Yandex/Avito как target непригодны (0 % coords), и чинить это геокодингом до замера качества адресов — работа с неизвестным выходом.

## Открытые вопросы (требуют измерения до реализации)

1. Величина калибровочной поправки ask→deal (по парам листинг↔ЕГРН в одном доме).
2. Территориальная репрезентативность CIAN-выборки относительно полного стока apartment НСПД (протокол ADR-0028).
3. Качество геокодинга адресных строк Yandex (доля уверенных матчей) — gate для варианта (в).
4. Режим смешения target'ов, если (б) принят: замена `cost_index` vs multi-source target с весами — отдельный эксперимент на квартете.
5. Доля CIAN-листингов, не проходящих join к НСПД (оценка масштаба возможного отравления выдачи, см. риск выше); судьба блока страниц 25–30 и хвоста >54.

## Последствия (если (б) принято)

- Новый ETL-шаг: чистка CIAN-листингов (квантильная фильтрация ₽/м²) → join к объектам НСПД по geo+area → строки gold-уровня с market-target для apartment.
- Контракт данных: target-колонка apartment получает второй источник; пайплайн должен явно различать `cost_index` (interim) и `ask_rub_per_m2` (listings, скалиброванный).
- Переобучение квартета apartment (ADR-0016) на новом target с замером против `cost_index`-baseline на тех же фолдах.
- Трек 1 (ADR-0010) частично разблокируется: market-target появляется для apartment; house/commercial/landplot остаются заблокированными (нужны сделки/ДКП или иной источник).
- Блок 6 (темпоральные срезы) по-прежнему blocked: у листингов есть дата объявления, но это дата ask, а не сделки — достаточность для временной оси требует отдельной оценки.
- Обновить статусную строку target в [info/project.md](../project.md) после реализации.
